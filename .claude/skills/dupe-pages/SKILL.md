# Dupe pages

The pages are generated by `build-dupe-pages.js` from three files:

| File | What it holds |
|---|---|
| `dupe-shades.js` | Which shades get a page, and per-shade overrides |
| `dupe-picks.json` | Which matches each page lists (written by the picker) |
| the live catalogue | Colors, photos, prices (fetched on every run, needs the network) |

Never edit the generated pages in `dupe-finder/<brand>/<shade>/` by hand.

Every command below needs node on the PATH first:
`export PATH="$HOME/.nvm/versions/node/v20.20.2/bin:$PATH"`

## Choosing the matches: the picker (the user does this)

Each page has two lists: 5 closest matches, and 5 closest under $15 (the `$` tier). Candidates are already
limited to bullets, liquid lipsticks and stains in the same or a similar finish (`LISTED_FORMATS`,
`SIMILAR_FINISHES`).

1. Make sure the site is served on 8080 (`npm exec serve /Users/connie/dev/lipstick_website -- --listen 8080`).
2. Run `npm run dupes:pick` in the background. When it prints `Pick the matches at http://localhost:8081`,
   give the user that link. It shows each shade's 10 closest candidates per list; they click up to 5 in each
   and press **Save picks and rebuild**. That writes `dupe-picks.json` and rebuilds only the pages whose picks
   (or a listed product's photo) changed.
   "Change photo" under a card swaps that product's photo for a pasted image link or an uploaded file. It
   applies on every page that lists the product. Chosen photos are kept in `dupe-picks.json` under `photos`
   (`brand|shade` → link, or `dupe-photos/<file>.webp` for an upload, kept in `dupe-photos/`; commit that
   folder). "Reset photo" goes back to the catalogue's.
3. They can look at the result on localhost:8080 (each section has an "Open page →" link) and keep
   adjusting. Stop the server when they're done.

Don't pick for the user. If they ask you to swap one match ("replace X with the next one"), the picker is
the place to do it. To do it yourself, edit that page's list in `dupe-picks.json` (keys are
`brand|shade` exactly as the catalogue has them, lowercase) and run `npm run build:dupes`.

A page with no picks lists its 5 closest. If a pick drops out of the catalogue after a new dataset, the build
warns and fills the gap with the closest unpicked match; rerun the picker to check those pages.

## Adding a shade

1. Add an entry to `SHADES` in `dupe-shades.js`: `brand` and `shade` exactly as the catalogue has them
   (lowercase), `product` when the shade is sold in several lines, `name` (how to print it), `short` (the
   shade alone, for headings), and `brandSlug` only if the brand's slug would be long. **The page URL comes
   from `brandSlug`/`brand` and `shade`; never change these for an existing page, its URL is indexed.**
2. Run the picker (above) so the user picks its matches.
3. `npm run build` too: the dupe finder's write-up links every page from `SHADES`.

## Per-shade overrides (in `dupe-shades.js`)

- `chartHex: '#rrggbb'` — the catalogue's color for the shade is wrong. The page ranks matches from this
  color the way the color chart does, and its "Filter all" links open the color chart. Remove it once the
  dataset is fixed (Pillow Talk has one now).
- `swatch: '/dupe-finder/assets/<name>.webp'` — a swatch photo shown beside the product in the hero. Save
  the user's image as WebP in `dupe-finder/assets/` with sharp; the cleanup step keeps it. Name it
  `<page-slug>-swatch.webp` (e.g. `mac-ruby-woo-swatch.webp`), resize to fit 480px and trim white borders. Then rebuild
  only that page: `npm run build:dupes -- --only mac/ruby-woo` (page keys as in `dupe-picks.json`, comma-separated).
  A page with a swatch has no lip drawing; `swatchLip: true` puts it over the swatch's bottom-right corner.
- `skip: ['brand|shade']` — never offer this match on that page (e.g. a duplicate listing of the same
  lipstick, a product whose photo can't be downloaded). Prefer the picker; use skip when it would keep
  coming back.

Photos: the build saves each listed product's photo as `dupe-finder/assets/<brand-product-shade>-144.webp`
(card) and `-240.webp` (detail view). If the retailer blocks a download, the build warns `no image for …`;
either drop it in the picker or put the files at those paths (full path:
`/Users/connie/dev/lipstick_website/dupe-finder/assets/…`). Check which page lists a product with
`grep -l "<shade>" dupe-finder/*/*/index.html` before naming it to the user.

## Checking

After any rebuild, serve on 8080 and check the changed pages in a headless browser (Playwright is installed)
at 1280px and 390px: no horizontal overflow, every card image loads, a card click opens the detail view.
If the filter links changed, open a few and make sure each shows results.

## Shipping

Commit the pages, `dupe-finder/assets/` (new and deleted photos), `dupe-photos/` (uploaded photos), `dupe-picks.json`, `dupe-shades.js`,
`sitemap.xml` (the build updates the pages' lastmod) and any script changes. Then follow the `ship` skill.
